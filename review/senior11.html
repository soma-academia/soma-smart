S13 · Number Systems & Codes

Data representation · CBE strand · Grade 11 · 1.1 Data Representation · lesson page

Reading cards

🔢 Four number systems Card 1

Computers store everything as binary (base 2: digits 0 and 1). People use decimal (base 10). Programmers often use octal (base 8: digits 0–7) and hexadecimal (base 16: digits 0–9 then A–F, where A = 10 and F = 15), because they are short ways to write long binary numbers.

➗ Decimal to binary Card 2

Divide by 2 again and again, writing down each remainder, then read the remainders from the bottom up. 13 ÷ 2 = 6 r1, 6 ÷ 2 = 3 r0, 3 ÷ 2 = 1 r1, 1 ÷ 2 = 0 r1, so 13 = 1101 in binary. The same method works for octal (divide by 8) and hex (divide by 16).

✖️ Back to decimal with place values Card 3

Each place is worth a power of the base. In binary the places are 8, 4, 2, 1 from the left: 1101 = 8 + 4 + 0 + 1 = 13. In hex the places are 256, 16, 1: 2F = 2 × 16 + 15 = 47.

🧩 Binary, octal and hex shortcuts Card 4

One hex digit is exactly 4 bits, and one octal digit is exactly 3 bits. So group binary from the right: 1111 1010 = FA in hex, and 011 111 010 = 372 in octal. This is why hex is used for colours (#FF0000 is red) and memory addresses.

🔤 Character codes: ASCII, EBCDIC, BCD Card 5

Text is stored as numbers using a coding scheme. ASCII (American Standard Code for Information Interchange) gives each character a code (A = 65, a = 97, 0 = 48). EBCDIC (Extended Binary Coded Decimal Interchange Code) is an older scheme used on IBM mainframes. BCD (binary-coded decimal) stores each decimal digit in its own 4 bits: 59 becomes 0101 1001. Unicode extends ASCII to cover every language, including emoji.

Narration

  • Computers use binary; people use decimal; programmers also use octal and hex.
  • Hex digits go from 0 to 9, then A to F, where F means fifteen.
  • To convert decimal to binary, keep dividing by two and read the remainders upwards.
  • Binary place values are 8, 4, 2 and 1, doubling each time.
  • One hex digit is four bits, and one octal digit is three bits.
  • ASCII codes the capital letter A as 65.
  • BCD stores each decimal digit in its own four bits.

S14 · Binary Arithmetic

Signed numbers, addition and subtraction · CBE strand · Grade 11 · 1.2 Binary Arithmetic Operations · lesson page

Reading cards

➕ Adding in binary Card 1

Binary addition has four rules: 0 + 0 = 0, 0 + 1 = 1, 1 + 1 = 10 (write 0, carry 1), and 1 + 1 + 1 = 11 (write 1, carry 1). Add column by column from the right, just like decimal: 0101 + 0011 = 1000, which is 5 + 3 = 8.

🔓 Unsigned numbers Card 2

An unsigned number has no sign, so it can only be zero or positive. With 8 bits, unsigned values run from 0 (0000 0000) to 255 (1111 1111). If a result needs more bits than you have, it overflows and the answer is wrong.

± Sign and magnitude Card 3

To store negative numbers, one simple method uses the leftmost bit as a sign: 0 for positive, 1 for negative. In 8 bits, +5 is 0000 0101 and −5 is 1000 0101. The problem: it has two zeros (+0 and −0), and adding signed numbers this way does not work directly.

🔁 One's and two's complement Card 4

One's complement makes a number negative by flipping every bit: +5 = 0000 0101 becomes 1111 1010. Two's complement flips every bit and then adds 1: −5 = 1111 1011. Two's complement has only one zero, and computers use it because ordinary addition then works for negative numbers too. With 8 bits it covers −128 to +127.

➖ Subtracting by adding Card 5

Computers subtract by adding the two's complement. To work out 7 − 5: write +7 as 0000 0111 and −5 as 1111 1011, then add them, giving 1 0000 0010. Drop the extra carry on the left and the answer is 0000 0010, which is 2. One adding circuit can do both jobs.

Narration

  • In binary, one plus one is one-zero: write zero and carry one.
  • Unsigned eight-bit numbers go from zero to two hundred and fifty-five.
  • Sign and magnitude uses the first bit as the sign, but it has two zeros.
  • One's complement flips every bit.
  • Two's complement flips every bit, then adds one.
  • Eight-bit two's complement covers minus one hundred and twenty-eight to plus one hundred and twenty-seven.
  • Computers subtract by adding the two's complement.

S15 · Logic Gates

Gates, truth tables and Boolean expressions · CBE strand · Grade 11 · 1.3 Logic Gates · lesson page

Reading cards

🚦 What a logic gate is Card 1

A logic gate is a tiny electronic circuit that takes one or more inputs, each 0 (off) or 1 (on), and gives one output. Gates are built from transistors, and billions of them inside a CPU (Central Processing Unit) make every decision a computer takes.

✳️ AND, OR, NOT Card 2

AND gives 1 only when all inputs are 1, like a lift that moves only when the door is closed AND a button is pressed. OR gives 1 when at least one input is 1. NOT has one input and flips it: 1 becomes 0 and 0 becomes 1.

🔄 NAND, NOR, XOR, XNOR Card 3

NAND is NOT AND: it gives 0 only when all inputs are 1. NOR is NOT OR: it gives 1 only when all inputs are 0. XOR (exclusive OR) gives 1 when the inputs are different. XNOR gives 1 when they are the same. NAND and NOR are called universal gates, because any other gate can be built from them alone.

📋 Truth tables Card 4

A truth table lists every possible input combination and the output for each. Two inputs give 4 rows (00, 01, 10, 11); three inputs give 8 rows. It is the clearest way to describe exactly what a gate or circuit does.

✍️ Boolean expressions Card 5

Gates can be written as Boolean algebra: A · B (or AB) for A AND B, A + B for A OR B, Ā (A with a bar, also written A′) for NOT A, and A ⊕ B for XOR. So Q = Ā · B means "output Q is 1 when A is 0 AND B is 1".

Narration

  • A logic gate takes inputs of zero or one and gives a single output.
  • AND needs all inputs on; OR needs at least one.
  • NOT flips its input.
  • NAND and NOR are the opposites of AND and OR, and they can build any other gate.
  • XOR is on when the inputs differ; XNOR when they match.
  • A truth table lists every input combination and its output.
  • In Boolean algebra, a dot means AND, a plus means OR, and a bar means NOT.

S16 · Logic Circuits

Combining gates to solve problems · CBE strand · Grade 11 · 1.4 Logic Circuits · lesson page

Reading cards

🔗 From gates to circuits Card 1

A logic circuit joins gates together so the output of one gate becomes the input of another. With a few gates you can describe real rules, like "sound the alarm if the system is armed AND a door OR a window opens".

🚨 A burglar alarm circuit Card 2

Let A = the alarm is armed, D = a door is open, W = a window is open. The rule is: Alarm = A AND (D OR W), written A · (D + W). An OR gate combines D and W, and its output goes into an AND gate together with A.

✍️ Boolean expressions from circuits Card 3

To find a circuit's expression, start at the inputs and write each gate's output in turn. An OR gate fed by D and W gives D + W. That goes into an AND gate with A, giving A · (D + W). Brackets show which part is worked out first.

📋 Truth tables for circuits Card 4

Evaluate the expression for every input combination. For A · (D + W): with A = 0 the output is always 0, so a disarmed alarm stays quiet. With A = 1 the output is 1 if D or W is 1. Three inputs give 8 rows to check.

➕ The half adder Card 5

Gates can also do maths. A half adder adds two bits: Sum = A XOR B, and Carry = A AND B. With A = 1 and B = 1: Sum = 0 and Carry = 1, giving 10, which is 2 in binary. Chain these together and you get the adders inside every CPU (Central Processing Unit).

Narration

  • A logic circuit feeds the output of one gate into another.
  • An alarm rule can be: armed AND, door OR window.
  • That is written A dot, bracket, D plus W.
  • Work out a circuit's expression gate by gate, from the inputs to the output.
  • A truth table checks the circuit for every input combination.
  • A half adder uses XOR for the sum and AND for the carry.
  • Chains of adders are how the CPU does arithmetic.

S17 · Network Standards & Protocols

TCP/IP, OSI and encapsulation · CBE strand · Grade 11 · 2.1 Computer Network Standards and Protocols · lesson page

Reading cards

📏 Why standards exist Card 1

Standards are agreed specifications that let equipment from different makers work together. IEEE (Institute of Electrical and Electronics Engineers) writes standards such as 802.3 (Ethernet) and 802.11 (Wi-Fi). The IETF (Internet Engineering Task Force) publishes the internet's protocols. ISO (International Organization for Standardization) created the OSI (Open Systems Interconnection) model. Because of standards, any phone can join any Wi-Fi network.

📜 Common protocols Card 2

HTTP (HyperText Transfer Protocol) and HTTPS (HyperText Transfer Protocol Secure) load web pages (HTTPS is the encrypted version). SMTP (Simple Mail Transfer Protocol) sends email; POP3 (Post Office Protocol version 3) and IMAP (Internet Message Access Protocol) collect it. FTP (File Transfer Protocol) transfers files. DNS (Domain Name System) turns names into IP (Internet Protocol) addresses. DHCP (Dynamic Host Configuration Protocol) gives devices an IP address automatically when they join a network. TCP (Transmission Control Protocol) delivers data reliably and in order; UDP (User Datagram Protocol) is faster but doesn't guarantee delivery, which suits video calls.

🧱 The TCP/IP model Card 3

The internet follows the four-layer TCP/IP model. Application: the protocols apps use (HTTP, SMTP, DNS). Transport: TCP or UDP split data into segments and use port numbers to reach the right app. Internet: IP addresses and routes packets across networks. Network access: sends frames over the actual medium, such as Ethernet or Wi-Fi.

🏢 The OSI model Card 4

OSI describes networking in seven layers: 7 Application, 6 Presentation (formats and encryption), 5 Session (manages conversations), 4 Transport, 3 Network, 2 Data link (frames and MAC (Media Access Control) addresses), 1 Physical (bits on the wire). OSI's top three layers map to TCP/IP's Application layer, and its bottom two to Network access.

📦 Encapsulation and decapsulation Card 5

When you send data, each layer wraps it with its own header on the way down: data becomes a segment (transport), then a packet (internet), then a frame (network access), then bits on the wire. The receiver unwraps the layers in reverse on the way up. This is called decapsulation.

Narration

  • Standards let equipment from different makers work together.
  • IEEE 802.11 is Wi-Fi, and 802.3 is Ethernet.
  • HTTP loads pages, SMTP sends email, DNS finds addresses, and DHCP hands them out.
  • TCP is reliable and ordered; UDP is fast but makes no promises.
  • TCP/IP has four layers: application, transport, internet and network access.
  • OSI has seven layers, from physical up to application.
  • Each layer adds a header going down, and removes it coming up.

🔺 The CIA triad Card 1

Network security protects three things. Confidentiality: only authorised people can read the data. Integrity: data is not changed without permission. Availability: systems and data are there when they are needed. Every threat attacks at least one of these, and every control protects at least one.

⚠️ Common threats Card 2

🔑 Access control Card 4

Give each user their own account with only the access they need (least privilege). Require strong passwords, and add multi-factor authentication, such as a code sent to your phone. Remove accounts when people leave. Keep server rooms and network equipment physically locked.

🔎 Keeping it secure Card 5

Install software updates promptly; they patch known weaknesses. Back up important data, offline or in a separate place, so ransomware can't hold you hostage. Classes, objects and the four principles · CBE strand · Grade 11 · 3.1 Object Oriented Programming (OOP) Concepts · lesson page

Reading cards

🧭 Two ways to organise programs Card 1

Procedural programming organises a program as a sequence of functions that act on data. Object-oriented programming (OOP) bundles the data and the functions that use it into objects, modelled on real things: a student, a bank account, a bus. Large programs are easier to manage and reuse this way. Java, C++, C# and Python all support OOP.

🧱 Classes and objects Card 2

A class is a blueprint; an object is one thing built from it. The Student class describes what every student has (attributes such as name and admission number) and can do (methods such as enrol() and pay_fees()). 🔒 Encapsulation and abstraction Card 3

Encapsulation bundles data and methods together and hides the inner details, so the data can only be changed through the object's own methods. A bank balance should change only through deposit() and withdraw(). Abstraction shows only what users need: you call send_money() without seeing all the steps inside.

🧬 Inheritance and polymorphism Card 4

Inheritance lets a new class reuse an existing one: Teacher and Student can both inherit name and phone from a Person class, then add their own features. Polymorphism means one method name behaves differently for each class: area() works out a circle's area one way and a rectangle's another way.

🗂️ UML class diagrams Card 5

Programmers plan classes with UML (Unified Modelling Language) class diagrams: a box in three parts, holding the class name, its attributes, and its methods.   • Abstraction shows only what the user needs.
  • Inheritance reuses a parent class; polymorphism lets one method act differently.

S21 · Relational Databases

Tables, keys and relationships · CBE strand · Grade 11 · 3.3 Relational Database Fundamentals · lesson page

Reading cards

🗃️ Databases and the DBMS Card 1

Data is raw facts (85, "Amani"); information is data with meaning ("Amani scored 85 in Maths"). A database is an organised collection of related data. A database management system (DBMS), such as MySQL, PostgreSQL, Microsoft Access or Oracle, lets you create, store, search and secure it. Metadata (stored in a data dictionary) is data about the data, such as each field's name and type.

🌳 Database models Card 2

Hierarchical databases store data as a tree (one parent, many children). Network databases allow many links between records. Relational databases, the most common today, store data in tables that are linked by shared values. Object-oriented databases store data as objects, like OOP (object-oriented programming) programs.

📊 Tables, records and fields Card 3

In a relational database each table holds one entity, such as Students. Each row is a record (one student), and each column is a field or attribute (name, admission number, class). Every field has a data type: text, integer, decimal, date or yes/no.

🔑 Keys Card 4

A primary key uniquely identifies each record, such as an admission number; it can never be blank or repeated. A foreign key is a field in one table that refers to the primary key of another, which is how tables link. A composite key combines two or more fields to be unique. A secondary key is used for searching, such as a surname.

🔗 Relationships and ER diagrams Card 5

Tables relate one-to-one (a student has one ID card), one-to-many (one class has many students) or many-to-many (students take many subjects, and each subject has many students). A many-to-many link needs a linking table. An entity-relationship (ER) diagram plans all this: rectangles for entities, ovals for attributes, diamonds for relationships.

Narration

  • Data is raw facts; information is data with meaning.
  • A DBMS such as MySQL creates, stores and secures databases.
  • Relational databases store data in linked tables.
  • A row is a record, and a column is a field.
  • A primary key uniquely identifies each record; a foreign key links to another table.
  • Relationships can be one-to-one, one-to-many or many-to-many.
  • ER diagrams use rectangles for entities and diamonds for relationships.

Reading cards

💬 What SQL is Card 1

SQL (Structured Query Language) is the standard language for working with relational databases. Many DBMSs (Database Management Systems) use it, each with small differences: MySQL, PostgreSQL, SQLite, Oracle and Microsoft SQL Server. SQL statements are grouped by job: DDL (Data Definition Language) defines structure, DML (Data Manipulation Language) changes data, and DQL (Data Query Language) asks questions.

🏗️ DDL: defining structure Card 2

CREATE TABLE students (adm INT PRIMARY KEY, name VARCHAR(50), grade INT); builds a new table. ALTER TABLE changes it, for example to add a column. DROP TABLE deletes a whole table and all its data. Use DROP with great care: there is no undo.

✏️ DML: changing data Card 3

INSERT INTO students VALUES (1021, 'Amani', 11); adds a row. UPDATE students SET grade = 12 WHERE adm = 1021; changes matching rows. DELETE FROM students WHERE adm = 1021; removes them. Always include WHERE with UPDATE and DELETE; without it, every row changes or disappears.

🔍 DQL: asking questions Card 4

SELECT name, grade FROM students; lists those columns for every row. SELECT * picks all columns. WHERE filters rows (WHERE grade = 11), ORDER BY sorts (ORDER BY name), and GROUP BY groups rows for summaries, such as SELECT grade, COUNT(*) FROM students GROUP BY grade; which counts the students in each grade.

🔗 Relationships in SQL Card 5

A FOREIGN KEY constraint links tables, so the database refuses a student whose class_id doesn't exist. A JOIN combines related tables in one query: SELECT students.name, classes.teacher FROM students JOIN classes ON students.class_id = classes.id; shows each student with their class teacher.

Narration

  • SQL is the standard language for relational databases.
  • DDL defines structure: create, alter and drop.
  • DML changes data: insert, update and delete.
  • DQL asks questions with select.
  • Always use where with update and delete, or every row is affected.
  • order by sorts results; group by makes summaries like counts.
  • A join combines related tables in one query.

S23 · Web Development

HTML, CSS and dynamic web apps · CBE strand · Grade 11 · 3.5 Web Development Fundamentals · lesson page

Reading cards

🌐 Web words Card 1

A web page is one document; a website is a group of linked pages; a web application does work for the user, like booking a bus ticket. The web follows the client–server model: your browser (the client) asks a web server for a page using HTTP (HyperText Transfer Protocol), and the server sends it back.

🧱 HTML: structure Card 2

HTML (HyperText Markup Language) gives a page its structure using tags in angle brackets. Every page has <html>, a <head> holding the <title>, and a <body> holding the content. Common tags: <h1> heading, <p> paragraph, <a href="..."> link, <img src="..." alt="..."> image, <ul> and <li> lists, <table> tables, <form> and <input> for user input.

🎨 CSS: style Card 3

CSS (Cascading Style Sheets) controls how a page looks: colours, fonts, spacing and layout. Inline CSS goes in a tag's style attribute. Internal CSS goes in a <style> block in the head. External CSS lives in a separate .css file linked to many pages, which is the best way to keep a whole site consistent.

⚙️ Static and dynamic pages Card 4

A static page shows the same content to everyone, straight from a file. A dynamic page is built when you ask for it. Client-side scripts (JavaScript) run in your browser, for example checking a form. Server-side scripts (such as PHP, short for PHP: Hypertext Preprocessor) run on the server, often reading or saving data in a database.

🔄 A dynamic web app, end to end Card 5

A learner fills in a registration form and taps Submit. The browser sends the form to the server. A PHP script checks the data and saves it to a MySQL database with SQL (Structured Query Language). The server then sends back a confirmation page. Design first with a wireframe (a simple sketch of the layout), and add alt text so everyone can use the site.

Narration

  • A browser, the client, asks a web server for pages using HTTP.
  • HTML gives a page its structure with tags.
  • Every page has a head with a title, and a body with the content.
  • CSS controls colours, fonts and layout.
  • External CSS keeps a whole site looking consistent.
  • JavaScript runs in the browser; PHP runs on the server.
  • A dynamic app sends form data to a server script that saves it in a database.
